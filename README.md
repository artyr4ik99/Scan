# NetSuite — сканер сети + просмотр IP-камер

Инструменты для диагностики **своей** сети (или сети, на аудит которой у вас
есть явное разрешение): поиск узлов, определение, что это за устройство, и
подключение к нему — плюс полнофункциональный просмотрщик IP-камер
(RTSP/ONVIF) поверх того же сканера.

> ⚠️ Сканирование сети, подбор паролей и подключение к устройствам — только
> в сетях, которыми вы владеете или которые вам явно разрешили проверять.
> Несанкционированный доступ к чужому оборудованию запрещён законом.

## Файлы

| Файл | Назначение |
|---|---|
| `netid.py` | общий модуль определения устройств: MAC→производитель (OUI), догадка ОС по TTL, NetBIOS-имя, HTTP-баннер, SNMP sysDescr, SSDP/UPnP, классификация типа устройства |
| `topology.py` | построение топологии сети: локальная (из уже отсканированных данных) и через SNMP (LLDP-соседи + MAC-таблицы портов управляемых коммутаторов), раскладка для отрисовки и экспорт в Graphviz DOT |
| `netscan.py` | консольный сканер сети: находит узлы, определяет устройство, подключается (SSH/Telnet/веб/RDP/VNC/raw TCP), строит топологию (`--topology-dot`, `--snmp-topology`) |
| `netsuite.py` | GUI-приложение: просмотр нескольких IP-камер (RTSP/ONVIF) + окно «Поиск и идентификация узлов сети» с тем же функционалом, что в `netscan.py`, плюс подбор заводских паролей камер, добавление их в просмотр, экспорт в CSV/JSON и визуальная топология сети на Canvas |
| `requirements.txt` | зависимости для GUI (`netsuite.py`) |
| `.github/workflows/build.yml` | сборка `.exe` на GitHub Actions |

`netscan.py` зависит только от `netid.py` и стандартной библиотеки Python —
работает без установки пакетов. `netsuite.py` дополнительно требует
`opencv-python`, `pillow`, `numpy` (см. `requirements.txt`), а для записи без
перекодирования, аппаратного декодирования и звука — `ffmpeg`/`ffplay` в
PATH (необязательно).

## Запуск из исходников

```bash
pip install -r requirements.txt
python netsuite.py      # GUI: камеры + сканер сети
python netscan.py        # консольный сканер (можно и без requirements.txt)
```

`netscan.py` полезен сам по себе на Linux/сервере без графики; `netsuite.py`
— полноценное приложение с окнами.

## Сборка .exe через GitHub Actions

1. Создайте репозиторий на GitHub и положите в него все файлы из этой
   поставки, сохранив структуру папок (важно сохранить
   `.github/workflows/build.yml` именно по этому пути).
2. Запушьте код.
3. Соберите вручную: вкладка **Actions** → **Build EXE** → **Run workflow**.
   Либо автоматически — запушьте тег `vX.Y.Z` (например `v1.0.0`):
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
   В этом случае дополнительно будет создан GitHub Release с готовыми
   `NetSuite.exe` и `NetScan.exe` во вложениях.
4. Файлы `.exe` появятся:
   - во вкладке **Actions** → открыть завершённый запуск → **Artifacts**
     (архив `windows-exe`) — если запускали вручную без тега;
   - в разделе **Releases** — если собирали по тегу.

Workflow использует `pyinstaller --onefile --windowed` для `NetSuite.exe`
(без консольного окна) и `--onefile --console` для `NetScan.exe`.

## Сборка .exe локально (Windows)

```powershell
pip install -r requirements.txt pyinstaller
pyinstaller --onefile --windowed --name NetSuite netsuite.py
pyinstaller --onefile --console --name NetScan netscan.py
```
Готовые файлы — в папке `dist\`.

## Что умеет определение устройств (`netid.py`)

Для каждого найденного узла, без аутентификации на нём:

- **MAC и производитель** — из системной ARP-таблицы (только в своём
  L2-сегменте) и базы OUI-префиксов (IP-камеры, роутеры, NAS, ПК, IoT).
- **Догадка ОС** — по TTL ответа ping (≈64 — Linux/встроенные устройства,
  ≈128 — Windows, ≈255 — сетевое оборудование).
- **Имя узла** — обратный DNS и NetBIOS-имя (UDP 137).
- **HTTP-баннер** — заголовок `Server` и `<title>` страницы на открытом
  веб-порту.
- **SNMP sysDescr** — если открыт UDP/161 (минимальный SNMPv1 GET без
  внешних зависимостей).
- **SSDP/UPnP** — отдельная широковещательная кнопка поиска (роутеры, NAS,
  медиасерверы и т.п.).
- **Итоговый тип устройства** — эвристика по всем признакам: IP-камера/NVR,
  роутер/коммутатор, NAS, принтер, Windows/Linux-хост, IoT и т.д.

## Подключение к найденному узлу

И в `netscan.py`, и в окне сканера `netsuite.py` для каждого узла
предлагаются только те варианты, порты которых реально открыты:

- SSH, Telnet — через системный клиент (или встроенный `Raw TCP`, если
  внешнего клиента нет);
- открытие `http(s)://ip:port` в браузере;
- RDP (`mstsc` на Windows, `xfreerdp` на Linux);
- VNC (`vncviewer`/`remmina`/`vinagre`, если установлены);
- сетевая папка SMB (Проводник / `nautilus`/`dolphin`);
- «сырой» TCP-клиент прямо в приложении — для ручной проверки любого
  текстового протокола на любом открытом порту.

## Топология сети

Два способа, оба доступны и в GUI (`netsuite.py`, окно сканера), и в
консоли (`netscan.py`):

- **Локальная топология** — строится из уже отсканированных данных, без
  дополнительных сетевых запросов: этот компьютер → шлюз (если определён) →
  узлы, видимые по ARP (тот же L2-сегмент), остальные — через шлюз. Это
  оценка «что видно с этого компьютера», а не реальная карта портов
  коммутатора. CLI: `--topology-dot out.dot`.

- **Топология через SNMP** — настоящая карта по коммутаторам: обходит
  LLDP-соседей (кто с кем соединён) и таблицы MAC-адресов за портами
  (какое устройство подключено к какому порту) через стандартные
  BRIDGE-MIB/LLDP-MIB. Требует **управляемый** коммутатор с включённым
  SNMP (обычно read-only community, часто по умолчанию `public`) —
  домашние неуправляемые свитчи этого не поддерживают, тогда останется
  только локальная топология. CLI: `--snmp-topology 192.168.1.1
  --snmp-community public --snmp-dot out.dot`.

В GUI результат рисуется на Canvas (цвет по типу устройства, колесо мыши —
зум, перетаскивание — панорамирование), с кнопками экспорта в Graphviz DOT
и в изображение (.ps). DOT-файл открывается командой
`dot -Tpng out.dot -o topo.png` (пакет `graphviz`) или вставкой текста на
https://dreampuf.github.io/GraphvizOnline/.

## Известные ограничения

- MAC-адреса видны только в вашем broadcast-домене (VLAN); узлы за
  маршрутизатором найдутся по портам/баннерам, но без MAC.
- Определение ОС/типа устройства — эвристика, а не точный fingerprinting;
  возможны ошибки, особенно на нестандартных/закрытых файрволом узлах.
- `netsuite.py` — Tk-приложение; на Linux нужен системный Tk
  (`sudo apt install python3-tk`), если собираете/запускаете из исходников.
